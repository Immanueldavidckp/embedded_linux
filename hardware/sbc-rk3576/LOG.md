# LOG: what broke, how it was fixed

Interview-story bank for the RK3576 SBC hardware generation.

| # | What broke | Root cause | Fix / lesson |
|---|---|---|---|
| 1 | Datasheet pin table parsed 693/698 balls; five came out "duplicated" as `1AD2` | `pdftotext` wrapped long ball IDs: `1AD2` + `0` on the next line | Treat a lone digit on a continuation line as part of the ball ID. **Lesson:** verify a count against a known total (698) before trusting extracted data. |
| 2 | The reverse-polarity P-FET on the USB-C input had source and drain swapped | Wrote S=VBUS, D=SYS. The body diode then points the wrong way | Removed the FET instead: USB-C can't present reversed polarity, and SOT-23 would burn ~0.5 W at 3 A. **Lesson:** every protection part should answer "what failure does this prevent?" |
| 3 | KiCad 7 `kicad-cli` has no `sch erc` / `pcb drc` | ERC/DRC CLI arrived in KiCad 8 | Installed KiCad 9 from the official PPA. `add-apt-repository` was broken (python `apt_pkg`), so the key and sources list were added by hand. |
| 4 | 472 ERC "errors" on the first run | No global/project library tables (no `.kicad_pro` yet) | Added a project file plus `sym-lib-table`/`fp-lib-table` with `${KIPRJMOD}`. 1 real issue remained: RK806 `CS` typed bidirectional on a GND/PWR_FLAG net, changed to input. |
| 5 | `Connector_HDMI` library not found | KiCad 9 renamed it `Connector_Video` | Added a footprint-existence check over the whole design. |
| 6 | Duplicate references C501–C505 | Sheet 04 has >99 capacitors, so `sn*100+k` ran into sheet 05's range | Overflow to `C4100+`, plus a hard uniqueness assert in `build()`. |
| 7 | `pcbnew` segfault in `ZONE_FILLER.Fill()` | Filling zones on a board built in memory (not loaded from disk) crashes in 9.0 | Save, `LoadBoard()`, fill, save again. |
| 8 | DRC: "board outline not closed", holes at 0 mm from the edge | Corner arcs were drawn backwards (start/angle convention) | Use `SetArcGeometry(start, mid, end)`: explicit and unambiguous. |
| 9 | 199 parity warnings: pads missing `unconnected-(…)` nets | KiCad 9 gives every NC pin its own net; the PCB set no net | The PCB now takes nets from the schematic's exported netlist (like Update PCB from Schematic) and cross-checks them against `design.py`. |
| 10 | 6.3 V caps on 5 V rails | Default voltage in the cap helper | The helper forces ≥10 V on any 5 V net (MLCC DC-bias derating). |
| 11 | **PMIC rail map wrong in rev A0**: 8 of 10 bucks and 4 of 5 NLDOs on the wrong rail | Mapping was inferred from the reference schematic's text order; that text order is not the pin order | Wrote the board device tree from mainline `rk3576-rock-4d.dts` (same RK806S-5) and compared regulator by regulator. **Lesson:** cross-check hardware against the software description (DTS) of a shipping board. The two have to agree, and the DTS is machine-readable. |
| 12 | DRC said "499 unconnected" on two quite different boards | KiCad's report stops listing unconnected items at 499 | Read the true count from `board.GetConnectivity().GetUnconnectedCount()`: 1,789. **Lesson:** a suspiciously round or unchanged number is a cap, not a result. |
| 13 | LCSC FE1.1s symbol marks pins 12/13/28 as NC | Library symbol error. The datasheet has VD18_O / VD33 / VD18 there | Built the symbol from the Terminus datasheet pin table. **Lesson:** a downloaded footprint can be trusted for geometry; a downloaded symbol must be checked against the datasheet. |
| 14 | Passives placed on top of hub/Wi-Fi pins | EasyEDA courtyards outline only the body | Recompute courtyards from pad extents + 0.25 mm when importing LCSC footprints. |
| 15 | Freerouting stalled at ~990 unrouted for 2 h | 0.55 mm FCCSP: no room for dog-bones, and the router never puts vias in pads | `fanout.py`: 818 via-in-pad escapes before routing; bottom side under the BGAs reserved for them. |
| 16 | Routing runs lost twice at the 2 h limit | After `job_timeout`, Freerouting first runs an optimizer (or hangs) and only then writes the SES | End chunks by pass count (`-mp 6`), optimizer off, hard `timeout 105m`, import in a separate process. |
| 17 | Hundreds of "unrouted" GND/power pads the router ignored | It treats plane outlines as connected; real fills were islands | GND stub+via stitching; power pours with stitching; hide pours from the router's view. |
| 18 | KiCad 9 Python crashes after `BOARD.Remove(zone)` | Dangling SWIG wrappers | Strip zones from the file as text (`zones_strip.py`); run each step in its own process. |
| 19 | Re-route after clearing L4/L7 made no progress | Signals limited to 4 layers cannot escape a 0.55 mm FCCSP + LPDDR5 with a general-purpose autorouter | Stop automating here; route DDR/escape by hand, then autoroute the rest. **Lesson:** an autorouter is a finisher, not a BGA/DDR router. |
| 20 | Same stall with 5 signal layers (L4 shared, L7 power-only) and real pour islands as planes | 475 plane islands make each pass >1 h; the escape congestion under the BGAs is unchanged | Automated routing has plateaued under every configuration tried (4/5/6 signal layers, pours hidden/rectangles/islands). Remaining work is interactive. |
| 21 | Freerouting could not close the last 482 connections under any configuration | A general-purpose topological router does not search every free cell; most open connections were 0.5–5 mm gaps in dense areas | Wrote `maze_route.py`: rasterise copper at 25 µm, take the open connections from KiCad's DRC, run a multi-layer A* (C, `maze/astar.c`) through distance-transform clearance maps. First pass: 482 → 154. **Lesson:** a grid maze router finds any path that exists; it trades speed for completeness. |
| 22 | A new via landed 0.11 mm from an existing drill | The clearance maps were computed on the search window only; a hole just outside the window was invisible | Compute distance maps on the window plus a 1 mm apron. **Lesson:** a distance transform is only as good as its borders. |
| 23 | Clearance errors at existing vias that the router had kept clear of | With unconnected pads removed, a via has only a drill on unused layers; a later route of the via's own net landing on it makes KiCad add a pad, and that pad violates the earlier route's spacing | Treat own-net drills as obstacles except at the connection's own end items, and stamp the pad when a route does land on a via. |
| 24 | After a few dozen `board.Remove(track)` calls, KiCad's Python objects turned into bare `SwigPyObject`s | `Remove()` hands ownership to Python; when the wrapper is garbage-collected the C++ object is freed while KiCad still points at it | Keep every removed item referenced until the process ends (`GRAVE` list); one board per process. |
| 25 | DRC of a scratch copy showed 500 clearance errors and 199 bad vias | `cp board.kicad_pcb` without its `.kicad_pro`: kicad-cli fell back to default rules (0.2 mm) and lost the net classes | Always copy the project file with the board. **Lesson:** design rules live in the project, not the board file. |
| 26 | Three router processes in parallel (power / DDR+GND / other) finished fast, but the merge left 294 open vs 154 sequentially | Each worker routed against a board without the others' copper; overlapping routes had to be dropped at merge time | Parallelise by independent problems (agents: cleanup, power pours, length tuning), not by splitting one congested routing job. |
| 27 | Rip-up and reroute on top of Freerouting's routes cascaded (2,992 items ripped, 541 DRC errors), then, with a price and cap, made no net progress (191 → 199) | Vias added earlier in a round report `FlashLayer()=False`, so collisions were missed; and the old routes were long detours that blocked everything | Conservative via shapes, 60/cell price, max 8 rips per path. Then strip everything back to fan-out + stitching (`strip_routes.py`, 942 open) and re-route cleanly in priority order. **Lesson:** don't polish a bad routing; start again with a better order. |
| 28 | Ten eMMC balls could not be routed at all | U701 (0.5 mm eMMC) was never fanned out; routes crossed its ball field and six bottom-side pull-ups/decaps sat exactly under its via sites | `fanout_region.py U701 --relocate`: clear the ball field, slide the blocking parts 0.25–2.75 mm, locked via-in-pad in all 33 used balls. **Lesson:** fan out every BGA before routing, and keep the other side of a BGA clear of parts on via sites. |
| 29 | Power rails stayed islanded even with tracks | Bounding-box pours with "smaller box wins" let wide, few-pad rails take the area under the SoC; some core rails had no copper at all | `pour_fix.py` (parallel agent): plan each rail as a tree joining its pad/via groups, share the rest by proximity, one zone per piece. 521 → 209 open on the same routing. |
| 30 | BGA balls with a fan-out via still looked boxed in | KiCad's DRC names one anchor per open connection, often the ball pad; the router started from the pad only, and a dangling via-in-pad has no copper on inner layers (unused pads removed), so the way down was invisible | Route ends grow to all own-net copper connected to them, and may land on any own via of that cluster on a layer where its pad fits. |
| 31 | Rip-up with a 16-item budget turned 69 open into 150 | In the full area between SoC and LPDDR5 every new path displaces several others, which then displace more | Keep the rip budget small (8) and stop when a round makes no progress; finish the last connections by hand or with more signal-layer area. **Lesson:** when every route costs two, the board needs more room, not a smarter router. |
| 32 | Power connections closed by the router re-opened after every zone refill | Each round's new vias and tracks cut the pours into new islands, so ~25 power joins kept coming back | Re-plan pours with `pour_fix.py` after signal changes, not before; slow nets may cross the power layers (`--pwr-ok`) at 3× cost. 78 → 72 open, DRC clean. What is left (~45 high-speed nets in the SoC/LPDDR5 area) needs layer area, not more search. |
| 33 | 72 connections would not route on 8 layers, whatever the router did | Between the RK3576 and the LPDDR5 all four signal layers were full; rip-up only moved the problem | **Rev A2: 10 layers** (`stackup.py`): two signal layers added as dual striplines next to L3 and L7; `to_10layer.py` moved the routed board over intact (72 open before and after). One plain pass: 72 → 21. **Lesson:** count layers before blaming the router; a dense DDR fan-out needs 6 signal layers on through-hole vias. |
| 34 | Short gaps (0.1–0.8 mm) that the router "could not" close | (a) KiCad joins tracks only at end points, so two overlapping pieces stay apart while the grid sees one blob; (b) inside the 0.55 mm ball field no new via fits anywhere, so a partial route stranded on the wrong layer there can never be joined | (a) bridge KiCad's two anchors with a short segment; (b) strip those nets and re-route them from their pads (`strip_routes.py --nets`), so they change layer at their own fan-out via. 22 → 14 open, DRC clean. |
| 35 | Every targeted rip-up pass on the last ~15 came out about even (14 → 18 → 15) | The remaining ends sit in 2–20 mm² pockets walled in by neighbouring DDR/RGMII routes; moving one wall closes another | Stopped automation at 14 open, DRC clean; `cleanup.py` removed debris (dangling vias 145 → 77, stubs 108 → 34) and `tune_length.py` brought 22 of 24 complete pairs into skew tolerance. The last 14 are documented for interactive routing (layout_guide.md). **Lesson:** know when to hand over: a push-and-shove interactive router does in minutes what a grid router cannot. |
